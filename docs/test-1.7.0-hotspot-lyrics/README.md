# Тестовая 1.7.0: хотспот и тексты песен

Ветка: `test-1.7.0`. База изменений: `79385603cdd9c120845d00afc56a8764eea9adbc`.
Этот пакет предназначен для APK-артефакта GitHub Actions, без публикации GitHub Release и без нового тега.
Версия и пакет сохранены: `1.7.0`, versionCode `14`, `com.akira.island`.

## Хотспот

- Добавлены монитор состояния и разбор системных уведомлений точки доступа: broadcast не считается единственным достоверным источником.
- Состояние активной точки доступа сохраняется после одноразового уведомления и восстанавливается при переподключении слушателя.
- Количество клиентов показывается только при наличии достоверного значения. Неизвестное количество не заменяется нулём.
- Карточка открывает настройки точки доступа; предусмотрена совместная работа с музыкальной карточкой и дополнительным пузырьком. Входящий звонок сохраняет приоритет.
- Обновлены описания и соответствующие переводы настроек.

## Тексты песен

- Сбой точного запроса LRCLIB не обрывает остальные стадии поиска. Фильтры исполнителя, названия, версии и длительности сохранены.
- Обычный текст и отсутствие результата можно перепроверить; срок неполного кэша — две минуты. LRU ограничен 40 записями.
- Предусмотрен один ограниченный повтор при включённом экране и раскрытом музыкальном плеере. Смена трека и отключение функции отменяют прежний запрос; читаемый обычный текст не исчезает при неудаче повтора.
- Учитываются HTTP 429 и Retry-After, включая смену треков во время ограничения провайдера. HTTPS, ограничения адресов и размера ответа сохранены.
- Строка появляется целиком, без побуквенной заливки, и плавно сменяется по настоящим LRC-меткам. Поддерживаются свой цвет текста, перемотка, смена трека с тем же индексом строки и уменьшение эффектов.
- Обычный текст без временных меток остаётся прокручиваемым. Искусственная синхронизация для него не создаётся.

В первом Android-прогоне прошли 44 из 45 методов. В новом тестовом HTTP-стенде условие задержки первого трека ошибочно сопоставлялось со всей строкой URL, включая имя исполнителя второго трека. Оно исправлено на точное сравнение `track_name`. Повтор всех четырёх lifecycle-тестов прошёл (4/4), включая запоздалый ответ старого трека. Код приложения при исправлении тестового условия не менялся.

Регрессии включают медиасессии и паузу, уведомления, Liquid Glass, хотспот совместно с музыкой и вторым пузырьком, приоритет звонка, сводку, маршрутизацию записей, настройки и проверки APK установщиком. Android-проверки используют искусственные медиасессии и уведомления; это не подтверждение работы конкретной версии Spotify или диктофона на физическом телефоне.

Команды сборки и JVM-проверок:

```bash
./gradlew --no-daemon --max-workers=2 testDebugUnitTest lintDebug assembleDebug assembleDebugAndroidTest
./gradlew --no-daemon --max-workers=2 assembleRelease
```

Последняя команда создаёт оптимизированный **неподписанный** APK. Для распространения тестовой сборки используется существующий workflow, отдельно от публичного release-job. Ключи и пароли не входят в этот пакет.

Новые Android-классы: `LyricsLifecycleDeviceTest`, `LyricsRenderingDeviceTest`, `HotspotIntegrationTest`.
Новые JVM-классы: `LyricsLookupTest`, `HotspotTest`.

## Что ещё не подтверждено

- Реальный хотспот с нулём, одним и двумя клиентами на разных OEM, включая пользовательский симптом.
- Проблемный трек на Pixel 8 Pro владельца, настоящие Spotify и Яндекс Музыка.
- FPS и расход батареи на физическом устройстве.
- Обновление именно этого нового APK через встроенный механизм поверх опубликованной версии на физическом телефоне. Прежние проверки старых версий не подменяют этот сценарий.

Встроенное обновление, подпись, Manifest, разрешения и существующие музыкальные команды в этом пакете не изменялись. Готовность всей версии 1.7.0 к публичному выпуску этим отчётом не объявляется.
