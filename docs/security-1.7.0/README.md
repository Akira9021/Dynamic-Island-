# Проверка безопасности тестовой 1.7.0 — 6 ноября 2026

Проверяется собственный исходный код приложения и локальный тестовый эмулятор. Ключи и пароли, загруженные владельцем в чат, не читались. Исходники и APK не отправлялись во внешние сервисы анализа.

Использованы установленные навыки **performing-android-app-static-analysis-with-mobsf** и **testing-android-intents-for-vulnerabilities** из [Anthropic-Cybersecurity-Skills](https://github.com/mukul975/Anthropic-Cybersecurity-Skills). Локально запущен **mobsfscan 1.1.0 / Semgrep 1.172.0**, дополнительно выполнены ручная проверка и независимое чтение изменений агентом. Полный сервер MobSF, Drozer и Frida не запускались; их результатов этот отчёт не заявляет. `huashu-art-motion` предназначен для видеороликов и к аудиту Android-кода не применялся.

## Исправления

| Участок | Что изменено |
| --- | --- |
| Ответы сети | Ограничения действуют во время чтения: GitHub/погода — 1 МБ, лирика — 2 МБ. Раньше некоторые ответы читались целиком, а погодный лимит проверялся уже после выделения памяти. |
| Загрузка обновления | APK не больше 100 МиБ; проверяется объявленная и фактическая длина. Незавершённый `.part` удаляется. Готовый файл появляется после проверки. |
| Адрес APK | Принимаются HTTPS assets своего GitHub-репозитория. Перенаправления ограничены GitHub/CDN и числом переходов; HTTP, чужие домены и адреса с учётными данными отклоняются. Проверка TLS остаётся системной. |
| Подлинность APK | До открытия установщика проверяются пакет, ожидаемая версия и сертификат установленного приложения, включая подтверждённую Android цепочку смены ключа. Итоговую проверку установки также выполняет Android. |
| Отмена | Отмена корутины больше не превращается в обычную ошибку сети; частичный файл очищается. Проверка подписи при повторной установке выполняется вне UI-потока. |
| Повторная проверка обновлений | Установщик получает выбранный `Release` непосредственно из карточки/загрузки. Временное `Checking`/`Error` другой проверки не блокирует уже проверенный APK. |
| Диагностика оплаты | Маскирование длинных чисел перенесено в общий вход журнала; обрабатываются также номера карт с пробелами, дефисами и неразрывными пробелами. Обычные суммы сохраняются. Это не полная анонимизация произвольного текста. |
| Резервные копии | Отключены облачное резервирование и перенос private-данных: настройки содержат также изученные каналы уведомлений, контакты и шаги. Обычное обновление поверх приложения сохраняет локальные данные. Автовосстановление после удаления/переноса больше не обещается. |
| Компоненты | Системные службы сохраняют signature-разрешения Android; FileProvider остаётся неэкспортируемым и отдаёт только папку обновлений. Настройки и launcher alias рассматриваются отдельно от привилегированных служб. |
| Внешний preferences-intent | Неверный тип или повреждённый Parcelable в EXTRA_COMPONENT_NAME больше не выходит исключением из lifecycle MainActivity. На старом API применяется безопасный cast; неправильный extra не подтверждает путь восстановления. |
| Пояснение о банках | Убрано неверное общее утверждение «ничего не читает в банке»: функция оплаты может распознавать поддерживаемый платёжный UI. Инструкция прямо предлагает отключить службу и не обещает обойти банковскую защиту. |

Новый жест прокрутки запускается только выбранным пользователем действием острова. Он просматривает геометрию и доступные действия активного вертикального списка, без текста/описаний/снимков. Исключены собственное приложение, SystemUI и клавиатура; обход и Binder RPC выполняются вне Main, ограничены временем/узлами/шагами и отменяются при смене окна/блокировке. Это не новый сбор истории экрана.

Скрытие значка лаунчера отключает только alias; MainActivity, плитка, системный вход в настройки и явное открытие из острова остаются доступны. Preferences-action — экспортируемый маршрут UI, а не проверка личности отправителя: стороннее приложение может открыть настройки, но не может таким intent самостоятельно скрыть значок. Подтверждение пути возврата — защита от потери доступа, а не механизм авторизации.

## Разбор предупреждений сканера

Для анализа используется **объединённый release-манифест**, где присутствуют реальные `minSdk=26`, `targetSdk=35` и настройки приложения. Анализ одного исходного манифеста без Gradle ошибочно приписывал приложению старый target SDK и выдавал два сообщения StrandHogg. Дополнительно у MainActivity задана пустая task affinity.

- «Hardcoded key»: `settings_v1`, `apps` и `telephony` — имена настроек/внутренний идентификатор, а не пароли или криптографические ключи.
- Mutable PendingIntent находится в демонстрации ответа и нужен для RemoteInput. Он ограничен пакетом приложения; переносить это разрешение на произвольные внешние intents нельзя.
- Поддержка Android 8/9 означает поддержку старых ОС; исходный код приложения не может установить им системные патчи.
- Отсутствие pinning, root detection, SafetyNet, запрета всех скриншотов или Certificate Transparency отмечается инструментом информационно. Это не доказательство обхода TLS или утечки данных. Функции не добавлялись ради нулевого счётчика предупреждений.
- Semgrep не полностью разбирает составную Kotlin raw-string константу валют в `PayScreen.kt`. Этот участок просмотрен вручную и компилируется Kotlin; покрытие автоматического сканирования здесь частичное.

Окончательный [JSON локального сканирования](mobsfscan.json) содержит **9 групп правил**: 2 уровня WARNING и 7 INFO; единственное сообщение парсера — описанный выше `PartialParsing`. HIGH/CRITICAL этим сканером не обнаружены. Все исходные файлы снимка побайтно сверены с финальным `app/src/main`, кроме намеренно заменённого объединённого манифеста. Полные локальные пути в отчёте заменены относительными.

## Проверки

Окончательный JSON сканера приложен выше. Сетевые лимиты, политика HTTPS/redirects, адреса своих assets и маскирование диагностики проверены в модульных тестах; весь JVM-набор — 103 теста без ошибок. На Android 35 прошли три сценария подлинности/установки обновления: корректный APK принят, чужой пакет/версия/сертификат и повреждение отклонены, повторная ошибка проверки сети не блокирует выбранный файл. Четыре сценария лаунчера проверяют восстановление и неверные типы preferences-extra. Жест прокрутки проверен на настоящем списке с запретами чтения текста в производственном коде и проверкой потоков. Подробные результаты и исходные сбои: [verification.json](../maintenance-1.7.0/verification.json).

Сканер и ручное чтение не доказывают отсутствие всех возможных уязвимостей. Root/Play Integrity, банковские приложения и атаки на реальные телефоны в этот прогон не входили. Работа выполнялась на собственном коде и локальном эмуляторе; исходники/APK не отправлялись в сторонние сканеры.

Для проверки другого сертификата используется копия собственного debug APK, переподписанная одноразовым тестовым ключом, а не ключом владельца. Она не устанавливается: Android-тест получает путь через `-e foreignSigningApk /sdcard/Android/data/com.akira.island/files/security-fixtures/foreign-signing.apk` и обязан отклонить её.
