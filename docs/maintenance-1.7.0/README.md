# Доработка тестовой 1.7.0 — 6 ноября 2026

Ветка `test-1.7.0`, база `2f8fe51`. Публичный релиз не выпускается. Изменения сделаны после просьбы владельца исправить диктофон, различать виды записи, включить жидкое раскрытие по умолчанию и провести ревизию кода с агентами и установленными навыками.

## Запись

- Диктофон распознаётся также по подтверждённому уведомлению с временем/паузой, без обязательной кнопки «Стоп», включая foreground-уведомление без флага ongoing.
- Разделены запись звука, запись экрана, запись видео камерой и неопределённая запись. Звуковая волна применяется только к диктофону; экран и камера имеют собственные значки и подписи.
- Если источник не дал настоящее действие остановки, показывается «Открыть приложение». Кнопка «Стоп» не имитирует завершение записи.
- Пауза останавливает счётчик и волну; продолжение без текстового времени не прибавляет длительность паузы.
- Сохранение/обработка файла, загрузки и обычный таймер SystemUI не считаются активной записью. Статус времени имеет приоритет над датой в имени записи, а системный хронометр — над эвристикой текста.

Обычное приложение не может достоверно определить запись во всех чужих камерах/диктофонах, которые не передают доступных сведений. Использование микрофона не выдаётся за доказательство диктофона. Новых разрешений камеры/микрофона не добавлено.

## Настройки и оставшиеся пожелания

- Жидкое раскрытие включено в новых настройках по умолчанию; явно сохранённое `false` сохраняется. В существующих файлах настроек значения записывались с `encodeDefaults=true`.
- Новый таймер автоскрытия пустой капсулы: выключен / 5 / 10 / 20 / 30 / 60 секунд. Открытая карточка, активность, блокировка и калибровка не скрываются этим таймером. После скрытия остаётся небольшая область у камеры для возврата.
- Для режима камеры-капли доступен независимый верхний отступ −10…30 dp. Старое размещение не меняется, обычный отступ капсулы сохраняется отдельно.
- Португальский и казахский дополнены отсутствовавшими 200 строками каждый; новые подписи переводятся во все поддерживаемые таблицы.
- Для значка уведомления — единый выбор слева / по центру под камерой / справа. Выбор «аватар / значок приложения / без значка» сохранён; чувствительный аватар скрывается при блокировке. Старое расположение справа корректно наследуется.
- «Компактный счётчик» использует прежний режим ICON без сброса настроек. Считаются уникальные уведомления, известные острову, а не строки одного сообщения или все уведомления Android.
- Необязательная сводка в дополнительной панели: цифровые, раздельные или аналоговые часы; дата, заряд и ближайший будильник; отдельные страницы шагов и погоды. Выключена по умолчанию. Погода и шаги используют прежние источники; чувствительные сведения и действия скрываются при блокировке. При выключении возвращается прежний заголовок, без дублирования часов/шагов.
- Жест «Наверх страницы» вызывает действия доступного вертикального списка. Не читает его текст/описания, не использует координатные свайпы; ограничен временем, количеством узлов и шагов. Binder-обращения и обход выполняются вне Main. При смене окна, блокировке или ориентации запрос отменяется. Неподдерживаемый экран не выдаётся за успешно прокрученный.
- Учтён ListView Android 35: действие перехода в позицию может быть доступно при неизвестном числе строк/столбцов. Переход к строке 0 использует само объявленное действие после проверки вертикального списка. Исчерпание лимита поиска отличается от отсутствия поддержки. Проверка фактического завершения нативной анимации остаётся в тесте; бюджет работы приложения не увеличивался.
- Значок лаунчера скрывается только по явному действию после добавления плитки и проверки входа в настройки из неё. MainActivity остаётся доступной, удаление плитки возвращает значок. Вход из самого острова, поддерживающего уведомления и системных настроек остаётся явным. Старые закреплённые ярлыки и созданный лаунчером «Об этом приложении» могут оставаться — UI предупреждает об этом.

Сохранены «живые» примеры: `SettingsPreview.kt`, `AppearancePreview.kt`, `GlassSurface.kt`, `GlassMotion.kt` этим патчем не менялись. Общий дизайн приложения не переделывался. Лицензия по решению владельца не добавляется.

После уточнения о стиле iPhone новая сводка получила тонкие шевроны, три точки страниц и нейтральный полупрозрачный фон. Сохранены крупные области нажатия, описание текущей страницы для TalkBack и плавное перелистывание. Поиск дополнен ссылками на новые настройки; существующие разделы не дублируются.

### Что остаётся

- Раздельные проценты L/R/кейса Bluetooth без доступных данных конкретной модели; текущий общий заряд не заменяется вымышленными значениями.
- Face ID и ошибки чужой биометрии/PIN, выключение только домашнего Samsung Now Bar, скрытие чужих системных значков и универсальные индикаторы камеры/микрофона/геолокации: подтверждённых данных публичных Android API недостаточно.
- Полный центр управления iPhone и точная копия всего сценария #23. Добавленная сводка — ограниченная часть запроса.
- Универсальная прокрутка любого приложения: собственные Canvas/WebView/нестандартные списки могут не предоставлять нужных действий; длинный список без перехода в позицию может исчерпать лимит шагов.
- Запись приложением без доступного уведомления/статуса не определяется универсально. Обычное использование микрофона не считается диктофоном.
- Подавление чужих системных heads-up на всех телефонах (#15 и скриншоты): доступна инструкция настройки самим пользователем; обход DND/запрещённых каналов не добавлен.
- Аппаратная проверка ColorOS/Techno/Samsung/Xiaomi, настоящих звонков, оплаты, Snapchat, Spotify/YouTube Music и батареи. Эмулятор не подтверждает исправление каждого OEM-вылета, расхода заряда или совпадение всех версий LRC.
- Публикация в Google Play и создание Telegram-канала этим изменением не выполняются. Основной релиз остаётся отдельно от тестового артефакта.

## Очистка и производительность

- Удалены 56 импортов без обращений в исходниках, неиспользуемые getters `Ios.batteryCharging`/`Ios.batteryFull`, лишний `PayMonitor.isWallet` и drawable `ios_battery_charging`. `ios_battery_full`, используемый системными событиями, сохранён.
- Не удалялись миграции настроек, manifest-компоненты, динамические ресурсы и тестовые точки входа только из-за отсутствия текстового вызова.
- Повторное уведомление музыки с тем же token использует существующий MediaController. Список медиасессий обновляется без снятия всех callbacks при каждом событии.
- Аппаратная неизменяемая обложка имеет стабильный отпечаток в пределах одного bitmap и различается с другим объектом; не используется постоянно меняющийся `nanoTime` как обычный идентификатор аппаратной картинки.
- Шагомер подписан на изменение своей настройки; изменение погоды или ярлыков не пересоздаёт его слушатель. Вместо создания SimpleDateFormat на каждый шаг используется LocalDate: при смене часового пояса дата не застывает в старом поясе.
- Погода подписана на свои параметры и состояние экрана; несвязанные настройки не отменяют её запросы. Регулярные выражения поиска и служебных строк лирики переиспользуются.
- Частые часы записи обновляются раз в секунду и останавливаются при паузе. Проверки APK не выполняются в UI-потоке.

Очистка не означает сокращение числа строк любой ценой: проверки безопасности и новые функции добавляют используемый код. Реальный FPS, нагрев и процент экономии батареи требуют замеров на телефоне.

## Безопасность и агенты

См. [отдельный отчёт](../security-1.7.0/README.md). Агенты разделили запись, поведение, переводы, ревизию производительности и безопасность. Часть первых задач остановилась по лимиту; их незаконченные изменения проверены и завершены основным агентом. Независимые просмотры нашли четыре регрессии: продолжение записи, установку при повторной проверке обновления, открытие настроек при скрытом launcher и неверный тип extra в экспортируемом preferences-intent. Они исправлены и получили проверки.

Первый объединённый прогон дал 35 успешных сценариев, сбой прокрутки и пропуск из-за отсутствия подключённого Wi-Fi. Повторные прогоны выявили неизвестные размеры доступной коллекции и асинхронное завершение нативной прокрутки. После исправления переход проверен по фактической строке 0; событие отладки проверено на восстановленной сети. Исходные результаты и итог каждого метода с хешами APK сохранены в [verification.json](verification.json), без подмены неудачных попыток успешными.

Для воспроизведения: `./gradlew --no-daemon --max-workers=2 testDebugUnitTest lintDebug assembleDebug assembleDebugAndroidTest assembleRelease`; затем AndroidJUnitRunner и классы из verification.json. Для проверки другого сертификата нужен собственный debug APK, переподписанный одноразовым ключом, путь передаётся через `-e foreignSigningApk`; этот файл и ключ владельца не входят в репозиторий. Дополнительные условия для события отладки — подключённый Wi-Fi и подтверждение системного диалога на тестовом устройстве.

Изменения не считаются аппаратно подтверждёнными на всех OEM только по сборке и эмулятору. Процент экономии батареи, реальный FPS и работа каждого диктофона/банка/плеера требуют соответствующего телефона и источника данных.
